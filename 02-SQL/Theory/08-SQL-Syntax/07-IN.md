# Definition

The `IN` operator is used in SQL to match a value against a list of possible values.
It’s a cleaner alternative to writing multiple `OR` conditions.

&nbsp;

&nbsp;

# Syntax

```sql
SELECT column_name
FROM table_name
WHERE column_name IN (value1, value2, value3, ...);
```

✅ This returns all rows where the column value matches any value in the list.

&nbsp;

&nbsp;

# Example

## 1. Simple Use

```sql
SELECT *
FROM employees
WHERE department IN ('Sales', 'Marketing', 'Finance');
```

✅ Returns all employees with salary ≥ 40000 and ≤ 80000.

&nbsp;

&nbsp;

## 2. Equivalent Using OR

The above query is the same as:

```sql
SELECT emp_name, department
FROM employees
WHERE department = 'Sales' OR department = 'Marketing' OR department = 'Finance';
```

✅ But `IN` is cleaner and more readable.

&nbsp;

&nbsp;

## 3. Using NOT IN

To find employees not in IT or Finance:

```sql
SELECT emp_name, department
FROM employees
WHERE department NOT IN ('IT', 'Finance');
```

&nbsp;

&nbsp;

## 4. Using `IN` with a Subquery

You can also use a subquery inside `IN`.

```sql
SELECT emp_name
FROM employees
WHERE emp_id IN (
    SELECT emp_id
    FROM attendance
    WHERE status = 'Present'
);
```

✅ This selects employees whose IDs appear in the attendance table with status 'Present'.

&nbsp;

&nbsp;

# Key Points

| Feature          | Description                                                                            |
| ---------------- | -------------------------------------------------------------------------------------- |
| Case Sensitivity | Depends on database (MySQL – case-insensitive by default; PostgreSQL – case-sensitive) |
| Data Type        | Values inside `IN` must be of compatible types                                         |
| Performance      | For large lists or subqueries, indexes improve performance                             |
| Alternatives     | `EXISTS`, `ANY`, and `JOIN` can sometimes perform better for large datasets            |

&nbsp;

&nbsp;

# 🧠 Tip

If the subquery might return `NULL`, `NOT IN` can behave unexpectedly — better to use `NOT EXISTS` in such cases.
